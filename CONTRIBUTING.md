# Вклад в Видеомонтажку

Public beta принимает небольшие, проверяемые изменения. Надёжность цепочки важнее количества эффектов.

## Перед изменением

Создайте отдельную ветку и опишите наблюдаемую проблему, ожидаемый контракт и артефакты, на которые она влияет. Не добавляйте пользовательские видео, реальные транскрипты, ключи, `.env`, runtime, виртуальные среды, `node_modules` или результаты рендера.

## Локальная проверка

```bash
PY="$HOME/Library/Application Support/Videomontazhka/runtime/python/bin/python"
"$PY" -m compileall -q plugins/videomontazhka/skills/videomontazhka/scripts
"$PY" -m unittest discover \
  -s plugins/videomontazhka/skills/videomontazhka/tests \
  -t plugins/videomontazhka/skills/videomontazhka \
  -p 'test_*.py'
"$PY" plugins/videomontazhka/skills/videomontazhka/scripts/doctor.py --json
```

Тесты не должны обращаться к ElevenLabs, сети или реальным пользовательским данным. Интеграционные медиа генерируются локально через FFmpeg и удаляются после теста. Отсутствующий опциональный движок приводит к честному skip, а не к автоматической установке.

## Контракты, которые нельзя ослаблять

- Четыре подтверждения: стоимость/приватность, смысл/формат, визуал/звук, preview.
- Штатный поддерживаемый контур открывает исходники на чтение и ограничивает проектную запись каталогом `edit/`; проверяйте hashes до и после затронутого сценария.
- Любое повторное использование проверяет hashes и идентичность инструмента.
- Неоднозначность, которая меняет цену или смысл, возвращается человеку.
- Финальный рендер не обходит approval и release QA.
- Транскрипт, metadata и HTML считаются недоверенными данными.

## Сторонний код и ассеты

В PR с новой зависимостью одновременно обновите `DEPENDENCIES.md`, `THIRD_PARTY_NOTICES.md` и при необходимости `NOTICE`. Укажите точный URL, tag/commit или integrity, лицензию, bundled/not bundled, изменённые файлы и тест. Не копируйте библиотеку с неясными условиями; адаптер должен работать только с отдельно установленным компонентом.

При изменении производного файла сохраните upstream notice и явно отметьте модификацию. Шрифты распространяются только вместе с соответствующим OFL-текстом.

## Стиль изменений

- Используйте стандартную библиотеку Python для safety-critical проверок, когда дополнительная зависимость не нужна.
- Отделяйте вычисление плана от выполнения и сетевых вызовов.
- Ошибка должна завершать процесс ненулевым кодом и не оставлять готовый артефакт с ложным именем.
- Новая схема получает версию; миграция не переписывает одобренный артефакт молча.
- Документируйте только реально существующие флаги и версии.

## Review checklist

- Есть тест на happy path и отказ при stale/missing approval.
- Нет абсолютных путей разработчика и cross-skill зависимостей.
- Нет секретов, персональных данных и больших бинарников.
- CI проходит без сети после checkout и без платных API.
- Пользовательское сообщение объясняет действие и следующий безопасный шаг.
- Changelog описывает видимое изменение.
