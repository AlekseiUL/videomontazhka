# Приватность и стоимость

## Что остаётся локально

Инвентаризация, hashes, компактирование готовых транскриптов, смысловые и творческие планы, EDL, графика, рендер, QA и публикационный пакет выполняются локальными инструментами. Проект хранится рядом с исходниками в `edit/`; runtime — в per-user application data.

Codex получает только тот контекст, который нужен для решения: компактные фразы, manifests и выбранные кадры. Массовая выгрузка всех кадров не является нормальным режимом.

## Что может уйти наружу

При выборе ElevenLabs сервис получает аудиосодержимое подтверждённых файлов для транскрибации. Внешние visual/search сервисы не входят в обязательную цепочку. Если пользователь отдельно просит получить ассет из сети, это новый внешний источник с отдельной проверкой прав.

Перед отправкой агент показывает:

- provider и model identity;
- точные source IDs и абсолютные пути;
- отметку, находится ли каждый source вне папки проекта;
- общую и некэшированную длительность;
- `cached`/`will_upload` и что именно отправляется;
- где будет храниться ответ;
- одобряемый предел минут;
- наличие кэша и причину, почему он действителен или устарел.

## Почему нет зашитой цены

Тарифы и способ списания меняются, зависят от аккаунта и могут включать пакеты/кредиты. Жёсткая денежная цифра быстро станет ложной. Видеомонтажка фиксирует объективный объём — потенциально billable минуты; денежную сумму пользователь сверяет отдельно по текущему тарифу своего аккаунта.

Approval не разрешает «все будущие вызовы»: он связан с preflight identity,
точным набором разрешённых upload sources, раскрытием внешней передачи,
дословной цитатой пользователя и максимальным объёмом. Новый файл, изменившийся
hash/путь, другая модель или превышение лимита требуют нового подтверждения.

Для каждой пары `approval_id + source identity` разрешена только одна
HTTP-попытка. До сетевого запроса capability погашается через exclusive marker
в приватном per-user application data, после чего `attempt_started` записывается
в append-only `transcription_attempts.jsonl` с SHA-256 hash chain. Таймаут,
нечитаемый ответ или ошибка после начала запроса считаются израсходованной
попыткой: инструмент не угадывает, списал ли провайдер лимит, и не повторяет
запрос молча. Для повтора нужен новый preflight и новое явное подтверждение.

Внешний marker — намеренный второй предохранитель: удаление или rollback
проектного ledger не восстанавливает старое разрешение. Anchor хранится вне
проекта, привязан к approval nonce, preflight hashes и canonical `edit/` path.
Потеря application data, другой компьютер или другой путь проекта блокируют
новый upload до нового подтверждения. Этот реестр не содержит API-ключа или
аудио.

## Повторные запуски

Кэш предотвращает повторную оплату только если одновременно совпадают:

- SHA-256 source bytes;
- provider;
- model/version identity;
- формат обязательных metadata;
- успешное завершение и целостность transcript artifact.

Одинаковое имя файла не является совпадением. Обычный, неполный или не
привязанный к identity `.part` не является кэшем. Единственное исключение —
полный word-level response, уже полученный от провайдера и содержащий точную
встроенную cache identity: его можно атомарно восстановить локально без нового
upload. Одновременные batch-процессы сериализуются project lock-файлом.

После частичного успешного batch повторный запуск использует готовые
hash-bound кэши и продолжает только ещё не начатые sources. Если результат
попытки был неоднозначным или успешный кэш потерян, этот source блокируется до
нового preflight и approval.

Перед FFmpeg источник копируется через открытый file descriptor в приватный
temporary snapshot. Именно snapshot повторно сверяется с одобренными size и
SHA-256 и служит входом извлечения аудио; подмена исходного pathname между
preflight и upload поэтому не меняет отправляемые байты.

Текущая macOS beta создаёт полный private snapshot source и извлечённый WAV в
системной temporary-папке. Для длинного стрима заранее нужен свободный объём не
меньше размера крупнейшего source плюс WAV. При обычном завершении файлы
удаляются автоматически; после `SIGKILL` или отключения питания каталог с
правами только владельца может остаться до очистки temporary storage системой.

## Ключи

Поддерживаемые места — переменная процесса `ELEVENLABS_API_KEY` или явно переданный через `--env-file` product env file. Рекомендуемый путь такого файла — `~/Library/Application Support/Videomontazhka/.env`, права — `0600`.

Запрещённые места:

- Git и история Git;
- `.env` внутри clone;
- папка исходников и `edit/`;
- `project.json`, approvals и manifests;
- prompt, комментарий review, screenshot или лог CI.

Наличие ключа означает только техническую возможность, не пользовательское согласие.

## Минимизация данных

- Не транскрибируйте visual-only файлы.
- Не отправляйте повторно валидный кэш.
- Для чувствительного материала используйте предоставленный проверенный transcript или доступный локальный режим, если его явно сообщает текущая сборка; не называйте локальным режимом отсутствующую capability.
- Не сохраняйте токены авторизации в crash report.
- Публикуйте только финальные материалы, прошедшие ручной privacy review.

## Политика хранения

Проект не удаляет файлы автоматически: срок хранения определяет владелец материала. Минимальная разумная политика:

1. хранить source manifest и approvals для воспроизводимости;
2. ограничить доступ к transcript/preview тем же уровнем, что и к исходникам;
3. после публикации удалить ненужные temporary/cache файлы по явному списку;
4. перед удалением убедиться, что финал, субтитры, release pack и provenance сохранены;
5. не использовать broad recursive delete по переменным или домашней папке.

Намеренный полный rollback одновременно project state и всего
`VIDEOMONTAZHKA_HOME` находится за локальной trust boundary: эти артефакты
защищают от повторного запуска, сбоя и частичного отката, но не являются внешним
криптографическим журналом против владельца ОС.

## Перед публикацией

Человек должен проверить лица, экраны, уведомления, адреса, документы, имена, голоса третьих лиц, конфиденциальные цифры, права на музыку/B-roll и точность цитат. Автоматический QA проверяет технику и связи артефактов, но не знает всех договорённостей и правовых оснований.
