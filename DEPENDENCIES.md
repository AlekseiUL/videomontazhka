# Зависимости и воспроизводимость

Видеомонтажка разделяет исходный код, runtime и пользовательский проект. Git хранит только код, схемы, маленькие шаблоны, проверяемые lock-файлы и явно лицензированные шрифты. Среды Python/Node, модели, FFmpeg, кэши и видео создаются локально.

## Базовый слой

| Зависимость | Ограничение | Назначение | Входит в Git |
|---|---|---|---|
| macOS на Apple Silicon | Текущая beta-цель | Apple Vision и проверенная локальная цепочка | Нет |
| Codex | Актуальная версия с skills/plugins | Диалог, решения и approval workflow | Нет |
| Python | 3.11+ | Скрипты, схемы, QA и рендер-оркестрация | Нет |
| FFmpeg + ffprobe | Локальная совместимая сборка | Декодирование, монтаж, фильтры, звук, кодирование | Нет |
| NumPy | `2.4.6` | Численные операции | Нет |
| Pillow | `12.3.0` | Локальные карты и графика | Нет |
| requests | `2.34.2` | Явно одобренный сетевой вызов транскрибации | Нет |

Прямые Python-зависимости зафиксированы по версиям, но их транзитивное дерево пока не закреплено lock-файлом с hashes. Для публичного стабильного релиза следует выпустить такой lock; до этого фактически установленный набор фиксируется в runtime manifest.

## Изолированные опциональные runtimes

Creative Python runtime фиксирует `click 8.2.1`, `numpy 2.2.6`, `opencv-python-headless 4.12.0.88`, `platformdirs 4.11.2`, `scenedetect 0.6.7.1` и `tqdm 4.70.0`. Manim runtime фиксирует `manim 0.20.1`. Browser runtime фиксирует прямые npm-зависимости и integrity всех транзитивных пакетов в `creative-browser-package-lock.v1.json`.

Эти среды ставятся отдельно, потому что обычному разговорному монтажу они не нужны. Инсталляторы должны:

1. отказаться от неподдерживаемой платформы или неожиданной версии;
2. ставить только перечисленные версии;
3. проверить import/CLI smoke test;
4. сохранить версии, лицензии и hashes в runtime manifest;
5. не писать внутрь папки с исходными видео, кроме согласованного `edit/`.

## Невендоренные движки

HyperFrames, GSAP, FFmpeg, Manim, PixiJS, Three.js, Rough Notation, lottie-web и gl-transitions не являются частью исходного дистрибутива. Код интеграции не означает, что продукт передаёт их лицензию или право на коммерческое использование. См. [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Runtime и переменные окружения

Путь runtime должен задаваться конфигурацией продукта и не должен содержать абсолютный путь машины разработчика. Поддерживаемые внешние overrides перечислены в [.env.example](.env.example). Локальный `.env` не коммитится.

Рекомендуемая логика размещения:

```text
~/Library/Application Support/Videomontazhka/
├── runtime/
│   ├── python/
│   ├── creative-python/
│   ├── manim/
│   ├── hyperframes/
│   └── creative-browser/
└── transcription-approvals/  # private anchors and consumed markers; no keys/media
```

Конкретный путь сообщает `doctor.py`; документация не должна считаться источником истины вместо его вывода.

## SBOM

Репозиторий не распространяет собранный runtime, поэтому статический SBOM не выдаётся за список уже поставленных бинарников. Для каждого релизного архива runtime создайте CycloneDX/SPDX по фактически установленным пакетам, сохраните `ffmpeg -version`, hashes исполняемых файлов и все license texts. Не используйте lock-файл как доказательство того, что именно эти байты были установлены: это доказывает runtime manifest и его hashes.
